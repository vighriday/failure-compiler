Screens and Layout

Five screens, desktop-first. Click to expand.

Screen 1
Paste Plan
›

A text area. A brief prompt. No checklist yet.

  • Load example button: Saturday food distribution plan, no key needed.
  • AI key field: appears here when no key is set and the user wants to paste a custom plan.
Screen 2
Plan Map
›

Top: checklist view. Every job with a person and a backup, all ticked. It looks done. This is the before.

Middle: structured reading. Short plain statements, each sourced to a line of the original. Three provenance states per item:

  • Default: AI reading plus source line.
  • Corrected: AI reading struck through, correction marked "corrected by you." Source line stays.
  • Added: marked "added by you," no source line. Created because a rule asked a question.

Constrained choices only: pick from known people, vehicles, places; time picker; no free text. AI does not re-read after corrections.

Bottom: "What we'll test." Each failure type with its size. Preset picks: 15, 30, 45, 60, 90 minutes only.

Confirm button: active only when every item is confirmed and every plain rule passes.

Screen 3
Crash Test
›

A live-filling grid: 12 to 15 failure types across and down, around 100 tests. Cells fill in order as the checker runs. Accepted fixes flip changed cells with a short animation.

Count line (live): "105 tests: 1 single weak spot, 3 hidden pairs, 13 already broken by the weak spot, 88 survived."

Before/After toggle above the grid once any fix is accepted.

Preview banner when a fix is selected: "Previewing: Fix N." Changed cells outlined, new crosses distinctly marked, count line shows projected numbers. "Cancel preview" restores exactly.

Screen 4
Broken Case Detail (panel)
›

Opens on the right when a cross is clicked. Grid stays on the left. No page navigation.

  • The failures, with a plain explanation of why the plan breaks.
  • For a hidden pair: note that each failure alone was fine. The three example pairs are Supply truck late + Ravi absent; Van late + Anita leaves early; Van late + Anita absent.
  • Timeline of the broken morning. A not-delivered route is drawn as never leaving, with the reason shown, e.g. “Van back 10:45. Loading team gone.”
  • Human cost: “Route C: 8 households not delivered.” For the other crosses: “Route A: 10 households not delivered” and “Routes A, B, C: 30 households not delivered. Nobody can open the loading area”.
  • Up to three fix cards, pre-scored. Turned-down fixes labelled with a one-line reason; previewable, not acceptable.

After accepting: grid re-tests in place, panel shows "Now survives," button to next broken case. When nothing is left: "All 105 tested scenarios survive" and "See report."

Screen 5
Report
›

Reached from "See report," available any time after the first run. One page in the app. Six sections plus an example-mode notice if applicable.

"Print or save as PDF" button uses browser print with a clean print layout.

Look and Feel

scope.md > Inspiration and Identity

A coordinator's run sheet, not a tech dashboard. Warm off-white paper background, near-black ink text. Calm, honest, no decoration that is not doing work.
Colour
Colour carries meaning only. Deep green for ticks and the main action. Brick red for crosses and broken states. Amber for question marks. Grey for dimmed marks. Everything else neutral.
Typography
IBM Plex Sans for all body text and UI. IBM Plex Mono for times, counts, and numbers so they line up. Clean and legible; nothing decorative.
Marks
Ticks and crosses are clean stroke marks, like a pen on a checklist. No emoji anywhere in the app. Colour and mark together so the grid is readable by everyone.
Timeline deadline
A solid red vertical line labelled "Noon: families waiting." Not a colour band or gradient.
Motion
Cells fill in order over a few seconds as the checker runs. Accepted fixes flip changed cells with a short animation. Both effects respect prefers-reduced-motion.
Colour palette (this document):  Deep green ticks   Brick red crosses   Amber question marks   Grey dimmed

The Checker's Three Honest Answers

Breaks
"This breaks your plan, and here is exactly how."
Survives
"Your plan survived everything we tested. That is not the same as 'your plan is safe.' It only covers what we tested."
Unknown
"I could not tell, because something is missing or unclear." Never treated as a pass.

The Report

Screen 5. Available any time after the first run. Six sections plus an example-mode notice. Browser print to PDF.

1. The plan Confirmed map and correction trail
Confirmed map with: "AI read 24 items, 2 corrected by you, 1 added by you."
2. What was tested Problem list, sizes, total
Each failure type with the size used, e.g. "Supply truck 45 minutes late." Total: "105 tests: every single problem and every pair."
3. What broke (before fixes) Weak spots, hidden pairs, dimmed results

Single weak spots and hidden pairs, each with its human cost. Dimmed results grouped: "13 pairs already broken by the key holder alone."

If removing a weak spot via a fix caused dimmed pairs to resolve or revealed a new hidden pair, the report shows that honestly.

4. Fixes Accepted and turned down
Every accepted fix: what changed and its result. Every turned-down fix: its one-line reason. Showing what did not work is part of the honesty.
5. After fixes Final count, or what is still broken
"All 105 tested scenarios survive." Or, if the coordinator stopped early, the remaining broken cases are listed here.
6. What was NOT tested Specific, not a disclaimer
  • Three or more problems at once.
  • Problem types outside the fixed list: bad weather, a volunteer getting sick halfway through, wrong addresses, running short on food.
  • Other sizes of the same problems: "the truck was tested 45 minutes late, not 90."
  • Anything the plan did not mention.
  • Any question-mark results, listed by name.
Example mode notice If applicable
"This report used a saved AI reading of the example plan."

States and Boundaries

First use / example mode
"Load example" available immediately, no key needed. Full flow runs on saved AI reading. Checker runs live.
Plan survives on first run
Count line reads "Your plan survived all 105 tested scenarios." Report offered directly. No broken cases to open.
No AI key
Paste area active; key field shown on Screen 1. Cannot submit a custom plan without a key.
AI key invalid or call fails
Clear error message, a retry button, and a suggestion to try the example plan instead.
AI reading fails format check
"The AI's reading did not pass the format check." Retry offered. Nothing reaches the plan map unchecked; the format check is part of the validation pipeline.
Pasted text is not a distribution plan
"This version only supports community distribution plans." Option to load the example plan.
Plan map: unconfirmed items
Confirm button inactive. Cannot proceed to the crash test.
Plan map: rule failure
Surfaces as a question. Confirm button inactive until resolved.
Grid: question mark cell
Never counted as survived. Listed by name in the report under "What was NOT tested."
Fix: turned down
Card visible and previewable; accept button absent.
None of the fixes pass
"None of these fixes worked." Option to ask for a new set of suggestions, once.
See report
Available any time after the first run. If cases are still broken, the report shows them.
Persistence
None. No accounts, no saved sessions. Closing the tab loses the run.

Product Decisions

Finish time is strict
One minute late is broken. The human cost display shows exactly how late; the coordinator decides what that means. Keeps the checker honest and results comparable.
Problem sizes: presets only
15, 30, 45, 60, 90 minutes. No free typing. Keeps results reproducible and the example story reliable.
Corrections do not re-trigger AI
Correction goes directly into the map. Preserves the pipeline: AI reads once, human confirms, checker acts on the confirmed map.
Turned-down fixes are visible
“Add Maya as backup driver for Route C” is turned down because the gap is loading, not driving. “One spare key” reveals Joel absent + Maya absent.
Dimmed pairs re-test after a fix
A fix removing a weak spot re-tests formerly-dimmed pairs. They may become ticks or reveal a hidden pair the weak spot was covering. Report shows this honestly.
Report after first run
"See report" is available any time after the checker has run at least once. A coordinator who stops fixing early gets a report showing what is still broken.
Report: browser print only
No custom export for the PoC. Nicer download is in Later.
Desktop-first
Side-by-side grid and panel layout requires screen width. Mobile is post-PoC.
Panel, not a separate screen
Grid stays visible throughout the fix flow. The user never loses sight of the full picture.

What We're Building

  • Screen 1: paste plan or load example; AI key field.
  • Screen 2: plan map with checklist view, sourced AI reading with correction trail, "What we'll test" with preset size pickers, plain rules validation, confirm button.
  • Screen 3: live-filling crash test grid with four cell states, count line, Before/After toggle, preview banner. Cells fill in order; accepted fix cells animate.
  • Screen 4: broken case detail panel beside the grid, with timeline, hard deadline line, human cost, scored fix cards, preview and accept flow, re-test in place.
  • Screen 5: report page with six sections plus example-mode notice, and browser print.
  • Example mode: saved AI reading ships with the app; full flow runs without a key.
  • Checker runs live in all modes.
  • A locked test confirms the example plan's three hidden pairs and one single weak spot never change.

Deferred and Non-Goals

  • Mobile layout deferred
  • Custom file export / nicer report download deferred
  • AI-suggested plan-specific failure types deferred
  • Live public link deferred
  • Accounts and saved sessions deferred
  • A second example type (event setup) deferred
  • File upload cut
  • Plans for any industry beyond community distribution cut
  • Three or more simultaneous failures cut
  • Connecting to other apps or messaging volunteers cut
  • AI having the final word on pass or fail cut
