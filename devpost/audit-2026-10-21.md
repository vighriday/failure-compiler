## Public-facing accuracy

The README, planning companions, app map, release record and deployment notes
now distinguish the following:

- Implemented slices and automated verification do not imply final human approval.
- Fingerprints identify normalized checker inputs, including IDs. Independently
  renamed AI readings need not have the same fingerprint. Role-aligned reading
  equivalence is measured separately.
- Repeatability is tested with the locked inputs and installed solver version;
  it is not a proof of identical output on every platform.
- A proved non-delivery has a concrete human cost. An unproved or ambiguous
  outcome is `?`, never a survivor or a credited repair.
- The reading schema does not ask AI to invent server metadata. Suggestion
  context does include the map fingerprint as an identifier, not a secret.
- Warm local timings are observations. Cold imports, host load and unmeasured
  hosting hardware can take longer.
- The converter was a bootstrap tool. It is not a lossless way to regenerate
  later manual accessibility and live-flow changes.
- The old `assets/submission` pack is archived. Its generated covers are artwork;
  its earlier screenshots are historical. The current gallery and sample report
  are actual saved-example output, with provider attribution and limits intact.
- The complete read-v3 comparison remains the basis for Gemini as primary.
  The incomplete read-v4 campaign establishes no new provider winner. No new
  provider requests or suggestion captures were made in this audit.

Dated earlier audit and revision records remain historical evidence. This
record and the current deployment note supersede stronger readiness claims in
those older entries.

## Public hosting is still separate work

Do not expose the current server to an untrusted public audience as-is:

- Local mode makes operator environment keys available to browser sessions;
  there is no enforced public mode that ignores those keys.
- The combined session/IP AI limiter can be reset with a new cookie. There is
  no independent IP budget or shared checker CPU/concurrency limit.
- Sessions, maps, reviews and caches have no general expiry or size bound.
- Public hosting still needs a tested HTTPS/proxy boundary, Secure cookies,
  private no-store responses, Origin checks and a request-body limit.
- The trusted unowned-map helper path must be excluded from public requests.
- No Docker or Podman engine is available here. Image execution, Linux startup,
  actual host capacity and cold-start performance remain unverified.

These are documented gaps, not newly implemented features. The supported local
launcher binds to loopback. See [deployment readiness](../docs/deployment-readiness.md)
for the exact boundary and dated official hosting references.

## Coverage and limits

The starting repository had **235 tracked files**, including 28 bundled workflow
files. The [per-file inventory](audit-files-2026-10-21.csv) lists the reviewed
snapshot, size, content hash, category and verification method. It covers every
tracked path plus the new application/test files, and excludes this report and
the inventory itself to avoid self-referential hashes. Text hashes normalize
CRLF to LF; binary hashes use exact bytes.

This combines source and claim review with executable checks. It does not claim
that every line received the same manual scrutiny: critical checker, gate,
session, credential, fix and report paths received focused review; compilation,
tests, browser checks and static/credential scans provide broader coverage.
Not every maintenance/capture script was executed, especially anything that
would call a provider. Binary assets were checked by format, dimensions,
references and report extraction; not every pixel is a new visual review.

The previous clean-clone proof is dated and tied to its recorded commit; it is
not relabelled as a fresh clone of this audit's fixes. No live provider call,
deployed host, cross-platform repeatability or production-security certification
is implied by the offline results.
